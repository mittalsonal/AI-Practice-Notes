# 🌐 MCP Server Notes

## Model Context Protocol Explained Simply

---

## 1. What is an LLM? 🤖

**LLM stands for Large Language Model.**

An LLM is basically a smart text-completion software.
It predicts the next word or response based on the data it has learned from books, websites, code, articles, and other internet-based content.

Examples of LLMs:

* GPT
* Claude
* Gemini
* LLaMA
* Mistral

---

## 2. What Can an LLM Do? ✨

An LLM can perform tasks related to understanding and generating text.

For example, it can:

✅ Write an essay
✅ Write a database query
✅ Explain code
✅ Generate documentation
✅ Create emails
✅ Summarize content
✅ Suggest solutions
✅ Write prompts

---

## 3. What Can an LLM Not Do Directly? ⚠️

An LLM cannot perform real-world actions by itself unless it is connected to tools.

For example, an LLM can write an email, but it cannot directly send that email.

It can write a database query, but it cannot directly run that query on your database.

It can suggest a code change, but it cannot edit your project files unless it has access to a code editing tool.

So basically:

**LLM can think, write, and suggest.**
**Tools help the LLM take action.**

---

## 4. Why Do We Need Tools? 🛠️

Tools allow an AI model to do actions beyond simple text generation.

For example:

### 🌍 Internet Search Tool

A tool like Perplexity can search the internet and bring fresh information.

Example:

> “Search the internet and find the latest AI news.”

Here, the LLM alone may not know the latest updates, but with an internet search tool, it can access current information.

---

### 🧑‍💻 Code Editing Tool

A code editing tool can help the AI:

* Read project files
* Edit code files
* Fix bugs
* Create new files
* Understand project structure
* Read console errors
* Apply user instructions inside the codebase

Example:

> “Fix this error in my React project.”

The AI needs access to your files, error logs, and project structure to properly solve the issue.

---

## 5. What is MCP? 🔗

**MCP stands for Model Context Protocol.**

It was designed by Anthropic.

MCP is a standard protocol that allows AI models to connect with external tools, data sources, and services in a structured way.

In simple words:

> MCP helps AI models talk to tools and use them properly.

---

## 6. Why is MCP Important? 🚀

Different AI models are good at different things.

For example:

* Claude may be good at reasoning.
* GPT may be good at writing.
* Gemini may be useful for certain testing or multimodal tasks.
* Some models may perform better with coding.
* Some models may perform better with documentation.

But the real power comes when these models can use tools properly.

So the main question is not only:

> “Which model is better?”

The better question is:

> “Which model has access to better tools and better context?”

MCP helps solve this by creating a common way for AI models and tools to communicate.

---

## 7. What is a Client in MCP? 💻

A client is the application that interacts with the MCP server.

Example of a client:

* Cursor
* Claude Desktop
* AI coding assistant
* Custom AI application
* IDE-based AI tool

The client talks to the MCP server and asks it to perform actions or provide context.

For example, Cursor can connect to an MCP server to:

* Read your project files
* Understand your repository
* Check errors
* Search documentation
* Access GitHub issues
* Use Slack messages as context

---

## 8. What is an MCP Server? 🖥️

An MCP server is a separate server that provides specific tools, resources, and context to the AI model.

Each MCP server is usually designed for a specific purpose.

For example:

### GitHub MCP Server

This server can provide access to:

* Repository issues
* Pull requests
* Code files
* Commits
* Discussions

### Slack MCP Server

This server can provide access to:

* Slack channels
* Team messages
* Discussions
* Error reports
* Internal conversations

### File System MCP Server

This server can provide access to:

* Read files
* Write files
* Edit files
* Create folders
* Understand project structure

---

## 9. Simple Example of MCP Flow 🔄

Suppose the user asks:

> “Check if the error I am getting in this repo is already mentioned in any GitHub issue or discussed in Slack.”

To answer this properly, the AI needs two types of context:

---

### 1. GitHub Context 🧑‍💻

The AI needs access to GitHub issues.

So it talks to the GitHub MCP server and asks:

> “Give me the latest list of issues from this repository.”

The GitHub MCP server provides fresh repository issue data.

---

### 2. Slack Context 💬

The AI also needs access to Slack conversations.

So it talks to the Slack MCP server and asks:

> “Check if this error was discussed in any Slack channel.”

The Slack MCP server provides relevant Slack messages.

---

### Final Result ✅

Now the AI has both contexts:

* GitHub issues
* Slack discussions

Then it can compare the error and give a useful answer.

This is the power of MCP.

---

## 10. What Does “Context” Mean in LLMs? 🧠

Context is one of the most important things for any LLM.

Context means the information given to the AI so that it can understand what is happening.

For example, the word **“fan”** can mean different things:

* A ceiling fan
* A fan of an artist
* A cooling fan in a computer

Without context, the AI may get confused.

But if we say:

> “The fan in my room is not working.”

Now the AI understands that we are talking about a ceiling fan.

So the more useful context we give, the better the AI can respond.

---

## 11. MCP Helps Provide Better Context 📦

MCP servers help AI models receive useful context from different sources.

For example:

* Project files
* GitHub issues
* Slack messages
* Database records
* API documentation
* Error logs
* CSV files
* Internal company tools
* Cloud services

This makes the AI more powerful because it is no longer limited to only its training data.

---

## 12. What is a Protocol? 📜

A protocol is a set of rules.

It defines how two systems should communicate with each other.

For example:

* How requests should be sent
* How responses should be returned
* What format should be followed
* How tools should be called
* How data should be shared

In MCP, the protocol defines how the client, server, tools, and model should interact.

---

## 13. Important MCP Concepts 🧩

MCP has some important building blocks:

---

## 14. Tools 🛠️

Tools are functions that perform actions.

Examples:

* Search the internet
* Read a file
* Write a file
* Run a command
* Fetch GitHub issues
* Read Slack messages
* Query a database
* Send an email

A tool is basically a function that helps the AI do real work.

Example:

```text
Tool: read_file
Action: Reads content from a file
```

```text
Tool: search_github_issues
Action: Searches issues inside a GitHub repository
```

---

## 15. Resources 📁

Resources are mostly data or attachments that are provided to the LLM.

Examples:

* CSV files
* Documents
* PDFs
* Code files
* API docs
* Project files
* Error logs

Resources help the AI understand the background information.

Example:

> “Here is a CSV file. Analyze the sales data.”

In this case, the CSV file is a resource.

---

## 16. Prompts 📝

Prompts are reusable templates for clients.

They help improve the way instructions are given to the AI.

For example, instead of writing a long instruction every time, we can create a prompt template.

Example:

```text
You are a senior software engineer. Review this code and suggest improvements.
```

Prompts can help:

* Improve user instructions
* Make vague prompts more detailed
* Standardize workflows
* Save time
* Make AI responses more accurate

---

## 17. Sampling 🔁

Sampling is a way to query or use other models.

For example, suppose I am using Claude, but I want:

* Gemini to create testing files
* GPT to write the README file
* Claude to review the architecture

With sampling, different models can be used for different tasks.

This is useful because every model has different strengths.

Example:

```text
Claude: Code reasoning
Gemini: Test generation
GPT: Documentation writing
```

---

## 18. Client and MCP Server Communication 🔌

In MCP, the client communicates with the MCP server.

The server exposes tools and resources that the client can use.

There are usually two communication methods:

### 1. Server-Sent Events

This allows the server to continuously send updates to the client.

It is useful when the AI needs streaming updates or real-time communication.

---

### 2. Message Endpoint

This is used when the client sends a message/request to the MCP server and receives a response.

Example:

```text
Client → MCP Server: Read this file
MCP Server → Client: Here is the file content
```

---

## 19. Simple MCP Architecture 🏗️

```text
User
 ↓
Client
 ↓
MCP Server
 ↓
Tools / Resources / External Services
```

Example:

```text
User asks a question
 ↓
Cursor receives the request
 ↓
Cursor talks to MCP Server
 ↓
MCP Server uses GitHub/Slack/File tools
 ↓
Context is returned to the AI model
 ↓
AI gives a better answer
```

---

## 20. Real-Life Example 🌟

User prompt:

```text
Fix the bug in my project and check if this error is already discussed in GitHub issues.
```

To solve this, the AI needs:

### Project File Access

To understand the codebase.

### Console Error Access

To understand the actual error.

### GitHub Issue Access

To check whether someone has already reported the same problem.

### Code Editing Tool

To fix the error in the file.

So MCP servers can provide all these tools in a structured way.

---

## 21. Final Simple Definition ✅

MCP is a protocol that helps AI models connect with tools, resources, and external systems.

It allows AI assistants to move from just answering questions to actually understanding context and performing actions.

In simple words:

> MCP is like a bridge between AI models and real-world tools.

---

## 22. One-Line Summary 🎯

**LLMs generate answers, but MCP gives them tools, context, and access to take useful actions.**
